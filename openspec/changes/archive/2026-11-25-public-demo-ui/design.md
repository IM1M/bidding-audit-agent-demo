# 设计文档

## Context

本变更为简历项目一的脱敏复现公开演示版本，仅实现前端演示页面，后端使用mock数据模拟。范围限定为前端展示层开发，不涉及真实AI组件、OCR处理、LLM推理等后端实现。

核心约束：
1. 完全复用现有`frontend-demo`规范的6个功能需求
2. 后端数据全部mock化，使用示例JSON
3. 技术栈保持简洁：FastAPI + Jinja2 + 原生前端技术
4. 视觉风格遵循简约企业设计原则

## 目标与范围

**设计目标:**
1. 实现FR-01～FR-06六个功能需求的完整演示
2. 创建专业、简约的企业风格界面
3. 提供流畅的用户交互体验
4. 确保代码结构清晰，便于维护和扩展

**不在范围内:**
1. 不实现真实OCR文档解析
2. 不集成LLM模型进行实际推理
3. 不实现Celery异步任务队列
4. 不涉及信创适配、等保国密等合规要求
5. 不连接真实数据库或外部API

## 决策

### 1. 前端技术栈：FastAPI + Jinja2 + 原生HTML/CSS/JS
**理由**：贴合简历技术栈，不引入React/TypeScript等新框架，保持技术栈简洁统一。Jinja2模板引擎与FastAPI集成良好，原生前端技术确保轻量化和可控性。

**视觉风格约束**：
- **颜色方案**：浅色主题，黑白灰为主色调；红/黄/绿作为业务状态色保留，但使用低饱和度版本（如#dc3545/#ffc107/#198754），禁止渐变、发光、霓虹效果
- **排版规范**：系统无衬线字体（如Inter, -apple-system, BlinkMacSystemFont），不对称栅格布局，充足留白（间距倍数：0.25rem/0.5rem/1rem/1.5rem/2rem）
- **内容克制**：不使用emoji、通用插画和营销文案，保持专业企业感
- **动效限制**：仅使用150-200ms的必要过渡动画（如状态切换、内容展开），无循环动画或复杂特效

**技术边界**：
- 不使用前端框架（React/Vue/Angular）
- 不使用TypeScript或复杂构建工具
- 不使用CSS预处理器（Sass/Less）
- 保持单页应用结构，通过AJAX与后端交互

### 2. 数据模拟策略：示例JSON + mock API
**理由**：演示版本不需要真实AI处理能力，通过预定义JSON数据模拟完整审核流程，既能展示功能又避免复杂后端依赖。

**数据设计**：
- **示例文档**：预定义1份脱敏招标文件元数据（名称、页数、条款数）
- **审核流程**：模拟六节点状态变化和时间进度
- **审查结果**：预定义红/黄/绿三级结论，包含置信度和锚点信息
- **证据链**：预定义规则依据和原文引用
- **指标数据**：预定义性能指标（审查时长、准确率等）

**API设计**：
- RESTful风格接口，返回JSON格式数据
- 支持模拟异步处理（通过定时器模拟处理时间）
- 提供节点重试、专家复核等操作接口

### 3. 架构设计：分层清晰，职责分离
**前端结构**：
- **模板层**：Jinja2模板负责页面结构和静态内容
- **样式层**：原生CSS实现视觉样式，遵循设计约束
- **脚本层**：原生JavaScript处理交互逻辑和数据绑定
- **数据层**：通过AJAX与mock API通信，管理应用状态

**后端结构**：
- **路由层**：FastAPI路由处理HTTP请求
- **数据层**：内存中维护模拟数据状态
- **服务层**：模拟审核流程状态变化
- **API层**：提供标准JSON接口

## 风险与权衡

**风险1：mock数据真实性不足**
- **缓解**：基于实际项目经验设计数据模型，确保逻辑合理性；明确标注数据为示例值

**风险2：交互体验不够流畅**
- **缓解**：精心设计过渡动画和状态反馈；充分测试不同操作流程

**风险3：代码结构过于简单**
- **缓解**：遵循清晰的分层架构；编写详细的代码注释；保持函数职责单一

**风险4：视觉设计不够专业**
- **缓解**：严格遵循设计约束；参考企业级产品设计规范；进行多轮视觉调整

**风险5：性能问题**
- **缓解**：前端代码优化，避免重绘重排；合理使用缓存；压缩静态资源
