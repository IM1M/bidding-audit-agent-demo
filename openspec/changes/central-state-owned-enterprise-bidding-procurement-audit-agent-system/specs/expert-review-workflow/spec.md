# Spec Delta

## Purpose

专家复核工作流管理，支持置信度阈值触发、多人复核、修正理由记录和样本回流，实现人在回路的半自动化审核流程。

## ADDED Requirements

### Requirement: 智能复核触发机制
系统SHALL基于置信度阈值、任务类型和风险等级智能触发专家复核，默认采用半自动模式，全自动仅用于低风险客观项。

#### Scenario: 置信度触发复核
- **WHEN** 审核结论置信度低于预设阈值（如<85%）
- **THEN** 系统SHALL自动触发专家复核流程，将结论标记为"待专家复核"

#### Scenario: 主观项强制复核
- **WHEN** 审核涉及主观判断项
- **THEN** 系统SHALL默认触发专家复核，确保主观判断的质量可控

#### Scenario: 规则冲突触发复核
- **WHEN** 不同规则对同一条款产生冲突判定
- **THEN** 系统SHALL自动触发专家复核，由专家进行最终裁定

#### Scenario: 新文档类型触发复核
- **WHEN** 系统首次处理某种文档类型
- **THEN** 系统SHALL对该文档的审核结果进行抽样复核，验证系统对新类型的适应能力

#### Scenario: 随机抽样复核
- **WHEN** 系统按预设比例进行随机抽样
- **THEN** 系统SHALL随机选择部分已自动通过的结论进行专家复核，持续监控系统质量

### Requirement: 专家复核工作台
系统SHALL提供专门的专家复核工作台，展示可疑点、证据链和原文位置，专家无需通读全文即可高效复核。

#### Scenario: 可疑点聚焦展示
- **WHEN** 专家进入复核工作台
- **THEN** 系统SHALL仅展示需要复核的可疑点和相关证据链，隐藏已通过的常规内容

#### Scenario: 原文快速定位
- **WHEN** 专家需要查看某条结论的原文依据
- **THEN** 系统SHALL根据证据链锚点直接定位到原文具体位置，支持高亮显示和上下文查看

#### Scenario: 对比分析工具
- **WHEN** 专家需要对比AI结论和人工判断
- **THEN** 系统SHALL提供并排对比视图，显示AI结论、证据链和专家修正选项

#### Scenario: 批量复核支持
- **WHEN** 专家需要处理多个待复核项
- **THEN** 系统SHALL支持批量操作，专家可以连续审核多个项目而不中断工作流

### Requirement: 专家修正与质量控制
系统SHALL要求专家修正时必须填写修正理由和依据条款，并建立三重防线确保修正质量。

#### Scenario: 强制修正理由
- **WHEN** 专家修改AI审核结论
- **THEN** 系统SHALL要求专家必须填写修正理由和依据的具体条款，否则无法提交

#### Scenario: 样本入池前质检
- **WHEN** 专家修正样本准备进入few-shot样本池
- **THEN** 系统SHALL进行去重、冲突检测和离群点过滤，关键项需要双人复核或抽样复核

#### Scenario: 专家权重管理
- **WHEN** 系统使用专家修正样本
- **THEN** 系统SHALL考虑专家历史准确率，对高准确率专家的修正给予更高权重

#### Scenario: 关键项双人复核
- **WHEN** 涉及高风险或重大金额的审核项
- **THEN** 系统SHALL强制要求双人独立复核，确保决策的审慎性

#### Scenario: 修正样本可回滚
- **WHEN** 发现错误或偏差的修正样本
- **THEN** 系统SHALL支持从样本池中下架该样本，避免污染few-shot学习过程

### Requirement: 专家回流与持续学习
系统SHALL按月将专家修正沉淀为带依据的few-shot样本，支持模型不重训也能持续对齐专家尺度。

#### Scenario: 月度样本回流
- **WHEN** 每月月底
- **THEN** 系统SHALL自动收集当月所有专家修正样本，进行质量过滤后加入few-shot样本池

#### Scenario: 样本分类与标签
- **WHEN** 专家修正样本进入样本池
- **THEN** 系统SHALL自动为样本打标签，包括审核类型、条款类别、修正原因和适用场景

#### Scenario: 样本相似度检索
- **WHEN** 处理新的审核任务
- **THEN** 系统SHALL基于向量相似度检索最相关的few-shot样本，作为LLM的上下文示例

#### Scenario: 样本效果评估
- **WHEN** 新样本应用一段时间后
- **THEN** 系统SHALL评估该样本对模型判断的影响，分析是否有效提升了审核一致性

### Requirement: 复核绩效与审计跟踪
系统SHALL跟踪专家复核绩效，所有复核操作留痕供审计，支持角色权限分离（专家、审查员、管理员、审计员）。

#### Scenario: 专家绩效统计
- **WHEN** 管理员查看专家工作统计
- **THEN** 系统SHALL展示专家复核数量、平均处理时间、与AI结论一致率、修正质量评分等指标

#### Scenario: 操作完整留痕
- **WHEN** 专家进行任何复核操作
- **THEN** 系统SHALL记录操作时间、操作内容、修改前后的结论差异和操作人信息

#### Scenario: 审计轨迹查询
- **WHEN** 审计人员需要追踪某次复核的完整过程
- **THEN** 系统SHALL能提供从AI初审到专家复核再到最终结论的全链路审计轨迹

#### Scenario: 角色权限控制
- **WHEN** 不同角色用户访问系统
- **THEN** 系统SHALL根据角色（专家、审查员、管理员、审计员）提供不同的功能界面和数据权限
