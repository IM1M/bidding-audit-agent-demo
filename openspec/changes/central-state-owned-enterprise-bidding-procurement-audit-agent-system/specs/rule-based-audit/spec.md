# Spec Delta

## Purpose

基于规则引擎的客观项审核能力，支持法规、制度、案例三层规则的结构化存储和版本化管理，实现确定性校验和冲突以规则为准的审核机制。

## ADDED Requirements

### Requirement: 三层规则体系管理
系统SHALL建立法规层、制度层、案例层三层规则存储结构，每条规则SHALL包含版本号、生效/失效日期、适用范围、依据原文和判定逻辑。

#### Scenario: 法规规则存储
- **WHEN** 管理员添加一条法规规则（如《招标投标法》第X条）
- **THEN** 系统SHALL将该规则存储在法规层，标记来源为正式法律法规，包含条款原文和适用条件

#### Scenario: 制度规则存储
- **WHEN** 管理员添加一条企业内部制度规则
- **THEN** 系统SHALL将该规则存储在制度层，按业务域组织，标记适用范围和业务场景

#### Scenario: 案例规则存储
- **WHEN** 专家审核结果经质检后作为判例
- **THEN** 系统SHALL将该案例存储在案例层，向量化后打标签，包括案例类型、相似度和置信度

### Requirement: 规则版本与回溯
系统SHALL为每条规则维护完整的版本历史，支持按时间回溯任意历史时点的规则状态。

#### Scenario: 规则版本查询
- **WHEN** 审计人员查询某次审核时依据的规则版本
- **THEN** 系统SHALL返回该时间点生效的规则内容和版本信息

#### Scenario: 规则变更追溯
- **WHEN** 规则发生变更
- **THEN** 系统SHALL记录变更时间、变更内容和变更人，维护完整的变更历史链

#### Scenario: 历史审核重演
- **WHEN** 需要复核历史审核结论
- **THEN** 系统SHALL能使用历史规则版本重新执行审核逻辑，验证结论一致性

### Requirement: 确定性规则引擎
系统SHALL提供基于规则引擎的客观项审核能力，支持逻辑表达式、条件判断和数值计算等确定性校验。

#### Scenario: 资格条件合规性校验
- **WHEN** 系统收到投标人资格条款
- **THEN** 系统SHALL根据资格规则库校验资质要求、业绩门槛、财务状况等客观条件

#### Scenario: 技术参数符合性校验
- **WHEN** 系统收到技术规格条款
- **THEN** 系统SHALL根据技术标准规则库校验参数范围、性能指标、测试方法等客观要求

#### Scenario: 商务条款合规性校验
- **WHEN** 系统收到商务条款
- **THEN** 系统SHALL根据商务规则库校验价格计算、付款条件、交付期限等客观约束

### Requirement: 规则冲突解决机制
系统SHALL提供明确的规则冲突解决策略，当多层规则发生冲突时，按照预设优先级（法规>制度>案例）进行判定。

#### Scenario: 法规与制度冲突
- **WHEN** 法规规则与企业制度规则发生冲突
- **THEN** 系统SHALL以法规规则为准，标记冲突并提供解释说明

#### Scenario: 多条规则同时适用
- **WHEN** 同一客观项有多条规则同时适用
- **THEN** 系统SHALL按规则优先级进行综合判定，记录所有适用的规则和最终判定依据

#### Scenario: 规则适用性判断
- **WHEN** 规则包含复杂的适用条件
- **THEN** 系统SHALL评估条款内容是否满足规则适用条件，仅当条件满足时才应用该规则

### Requirement: 规则更新与验证流程
系统SHALL提供"草稿 → 专家评审 → 影子模式 → 灰度 → 生效"的规则更新流程，确保规则变更的稳定性和准确性。

#### Scenario: 影子模式验证
- **WHEN** 新规则发布
- **THEN** 系统SHALL先在影子模式下运行，只记录判定结果而不影响实际审核，与专家结论进行比对验证

#### Scenario: 灰度发布
- **WHEN** 规则在影子模式下验证通过
- **THEN** 系统SHALL进入灰度发布阶段，仅对部分采购包生效，监控规则实际效果

#### Scenario: 规则回滚
- **WHEN** 新规则在灰度阶段发现问题
- **THEN** 系统SHALL支持快速回滚到上一稳定版本，不影响已完成的审核
