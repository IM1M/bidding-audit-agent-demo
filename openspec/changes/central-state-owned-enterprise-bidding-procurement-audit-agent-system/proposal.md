# 提案

## 背景与问题

企业招标采购审核流程目前面临双重效率瓶颈：一是专家产能严重不足，单份招标文件200-400页，专家通读需3.5小时，企业年处理数千个采购包，人工审核成为交付瓶颈；二是审核质量风险高，同类条款不同专家判定尺度不一，审计抽查时无法追溯"当时为什么这么判"，存在合规隐患。当前急需通过AI Agent技术将四道人工审核（采购需求、招标文件、投标资格、评标报告）自动化，提升审查效率65%，同时确保审核过程可追溯、判定尺度标准化。

## 变更内容

1. **引入AI驱动的招标文件审核系统**：基于LangGraph状态机实现六节点审核流水线（文档解析 → 条款抽取 → 客观/主观双分支判定 → 证据绑定 → 分级报告 → 专家复核）
2. **构建双路判定引擎**：客观项采用规则引擎（确定性校验），主观项采用LLM+few-shot+JSON Schema约束（结构化输出），冲突以规则为准
3. **实现文档结构化解析**：通过PaddleOCR+自研算法还原"章—节—条—款"四层结构树，确保每条结论都能回溯到原文位置
4. **建立知识库与专家回流机制**：法规、制度、案例三层规则结构化存储，专家修正按月回流为few-shot样本，持续对齐专家尺度
5. **部署全栈信创环境**：适配海光/鲲鹏CPU、麒麟/openEuler OS、国产数据库，满足等保三级和国密算法要求
6. **构建可观测性体系**：Langfuse实现全链路Trace，Prometheus+Grafana监控基础设施

**BREAKING**：需要改造现有采购系统的API接口，支持异步审核结果回调
**BREAKING**：需要对接企业统一身份认证系统，实现角色权限分离

## 系统能力

### 新增能力

- `bidding-document-parsing`：支持招标文档的OCR解析、版面分析和结构化重建，能还原章-节-条-款四级结构
- `clause-extraction`：从结构化文档中智能抽取采购相关条款，支持多文档类型（招标文件、技术规格书等）的可配置模板映射
- `rule-based-audit`：基于规则引擎的客观项审核能力，支持法规、制度、案例三层规则的结构化存储和版本化管理
- `llm-assisted-audit`：大语言模型辅助的主观项审核能力，支持few-shot学习、JSON Schema约束输出和模型热切换
- `evidence-chain-management`：完整的证据链管理能力，每条审核结论绑定原文锚点、抽取结构、规则依据、置信度等元数据
- `expert-review-workflow`：专家复核工作流管理，支持置信度阈值触发、多人复核、修正理由记录和样本回流
- `regulatory-compliance`：满足企业等保三级、国密算法、信创适配等合规要求的系统能力
- `observability-tracing`：全链路可观测性，包括LLM调用追踪、成本统计、节点级监控和审计日志

## 影响范围

1. **系统集成影响**：
   - 需要与采购系统API对接，拉取采购包信息，回写审核结论
   - 需要对接ERP获取物料和供应商主数据
   - 需要集成OA系统的审批流程
   - 需要对接企业统一身份认证（OAuth2/SAML/CAS/LDAP）

2. **技术架构影响**：
   - 引入LangGraph作为工作流编排引擎，Celery作为异步任务队列
   - 引入PaddleOCR作为文档解析基础，需要自研结构重建算法
   - 引入pgvector/openGauss DataVec作为向量数据库
   - 引入Langfuse作为LLM链路追踪工具
   - 需要构建模型抽象层，支持多模型（Qwen/GLM/DeepSeek）热切换

3. **部署环境影响**：
   - 需要全栈信创适配：CPU（海光/鲲鹏）、OS（麒麟/openEuler）、DB（金仓/达梦/openGauss）
   - 需要满足等保三级要求，日志留存不少于180天
   - 需要支持国密算法（SM2/SM3/SM4）的电子签章集成
   - 需要实现"数据不出域"的完全私有化部署

4. **业务影响**：
   - 单份文件端到端审核时间从3.5小时降至1.2小时（效率提升65%）
   - 自动审查约8分钟/份，专家产能瓶颈得到缓解
   - 跨专家复评结论一致率提升78%，审查准确率95%以上
   - 条款定位准确率从71%提升至94%，审计可追溯性大幅增强
